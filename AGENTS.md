# Repository development instructions

## Scope and provenance

Maintain RouteShelf Java as an independently implemented Google Drive client for Android. Support verified Google data connections in addition to system networking. See docs/PRODUCT.md for the current platform scope.

Do not copy, translate, rewrite section by section, import, compile, vendor or patch mizorewww/gdirect's GPL source, aria2 patches, native binaries, tests, IP seeds, assets or documentation. Use Android SDK, official Google APIs, public protocols and original implementation/tests. Reading the reference does not authorize importing its implementation. Standard properly licensed dependencies are allowed with reviewed notices. Do not imply Google or upstream author endorsement.

Project-owned source is GPL-3.0-only. See docs/LICENSING.md for the Android linking permission, earlier Apache-2.0 grants, and third-party terms. Do not change licensing or branding without a maintainer decision. Preserve the historical prototype ZIP and its original terms. Build from the tracked source.

## Android behavior and verification

1.0.2-preview/code 24 displays RouteShelf and preserves browsing/search/paging/sorting, shared drives/shortcuts, explicit opt-in file management/sharing/trash, native previews and exports, foreground uploads/downloads, and Material Drive-style navigation with a standalone unified SettingsActivity. Java IPv6 support remains; manual rechecks no longer reset live routes, diagnostics explain IPv6 eligibility, and the browser bottom system inset matches its navigation surface. See docs/IPV6.md, docs/PRODUCT.md, docs/design/ANDROID.md, docs/ACCEPTANCE.md and docs/DIRECT_NETWORK.md.

Network implementation: independent GTS-only trust store, normal/no-SNI/fixed g.cn TLS identity with logical Host separation, official non-Cloud IPv4 range filtering (a small attributed three-/24 bootstrap subset when the official catalog is unavailable), fast candidates before bounded expanded TCP discovery, up to eight verified IP/TLS combinations, explicit opt-in known relay, and checked media-only Google content redirects without credentials. Default remains Google-only. When relay consent exists, verify the fixed relay before blocking on official range/DNS discovery; successful preferred verification returns immediately, failure has a 5.5s/quarter-budget bound before Google fallback. Never silently enable relay consent. No arbitrary SNI, arbitrary relay, certificate forgery or trust-all fallback. Bundled public roots retain MPL-2.0, see docs/TRUST_ROOTS.md.

Still absent: full bundled official IP snapshot, desktop 0.9.0 self-managed refresh-token direct routing, transfer queue, offline sync, cross-process private transfer recovery, collaborative editing and mount. Do not claim official-app parity or all-network Google access. Official Android authorization/token acquisition/revocation uses Google Play services' system network.

The built-in Google candidates are six individually unverified hints are independently selected inside three /24 blocks mentioned in a dated Shanghai Unicom public report. Never describe these six IPs as individually tested in China. Do not copy the upstream seed file. Live official ranges override the subset, cancellation does not trigger fallback, and every candidate still needs current TLS/service verification. See google-bootstrap.json and docs/DIRECT_NETWORK.md.

ConnectionCheck is application-owned, single-flight and cancellable; screen exit/rotation must not cancel it. Do not restart scans until cancellation finishes or reset policy while a transfer is active. Actual requests bind a network epoch and recheck it plus the account after TLS, before HTTP transmission; cancellation/policy changes must not poison healthy route caches. Bootstrap keeps at most two in-range historical hints before packaged candidates, all requiring revalidation. Settings centralizes account, routing, transfer preferences and help; public one-transfer IP remains separate.

Current local baseline: 255 JVM tests per debug/preview variant, 11 standalone parsing/security checks, real IPv4/IPv6 loopback TLS and actual builds/Lint. Owner's 0.8.5 log records authorization, IPv4 API browsing and manual checks; older retained download events have no per-entry build attribution. See docs/history/CONNECTION_REPORT_0_8_5.md. The owner supplied a RouteShelf browser screenshot and reported needing a manual connection check. Current 1.0.2-preview automatic recovery, real-account transfer and China-network acceptance still need device results. Earlier releases and failed emulator runs do not establish acceptance for this version.

Navigation rendering must never dispatch listing requests. Guard both Material selected/reselected callbacks during programmatic synchronization and skip selection of an already selected item. Metadata GET attempts have 5s connect / 8s read / 12s whole-call maximums, preserving stricter caller/client limits. Media/export/range requests and writes retain their transfer timeouts. Whole-call timeouts are network failures, not user cancellation; cancellation/account/policy invalidation during body reads never rejects a healthy route. See docs/history/CONNECTION_LOOP_0_8_1.md for the regression evidence.

Preserve dev.gdirect.lite.preview, the retained private key outside Git, and config/preview-signing.json. Ordinary updates must not require new OAuth registration. Local DiagnosticLog is capped at 512 entries/128 KiB, stored privately with coalesced background I/O, viewed/copied/SAF-exported only on explicit user action. Disk failures and diagnostic callbacks must not block or fail network requests. Clearing during asynchronous restore must not resurrect old logs.

## Security and implementation

- Keep chain/hostname verification enabled. Fixed g.cn identity must verify g.cn under Google-only roots while preserving the checked logical service origin.
- Keep tokens out of URLs, logs, exported intents and unintended hosts. Default read-only remains locally read-only even if SDK returns cached wider grants; writes require actual scopes and explicit management choice.
- Do not replay uncertain writes; use bounded retries and version/integrity checks for transfers. Sensitive headers never go to media redirect destinations. Resource keys stay bounded/in memory and lease checks protect account changes.
- Shared access, destructive deletion and network mode consent must correspond to clear user actions. Never send unsolicited external messages through tools.
- Cloud tests follow environment network policy; no raw public-IP probing, proxy bypass or using CI as a fetch proxy. Distinguish loopback evidence from device/network tests.
- UI direction is close to Google Drive using own assets and Android Material components, with day/night, 48dp touch targets, font scaling, IME/system insets and accessible states. Do not invent features or claims to fill the interface.

Pure Google discovery pipelines up to 512 expanded addresses through 24 TCP and 6 TLS workers without stopping at 32 TCP answers or 48 expanded candidates. Do not re-probe failed fast addresses in the same expansion. A failed cached identity gets bounded same-IP alternate-identity verification before fresh discovery. Network handle or VPN-presence changes invalidate routes; guards check the live path before HTTP transmission. Settings uses AndroidX Preference and Material dialogs, saves mode flags atomically, and cancels an active check before applying a pending selection.

IPv6 discovery requires a global address and default route on the active Android network. Parse numeric literals without DNS; normalize before cache/log use; reject scopes, URI/port input and special-use candidates. Official IPv4/IPv6 ranges are independently reduced by Cloud exclusions. Preserve the original 512 IPv4 candidates and 24 TCP/6 TLS workers; allow at most 128 additional IPv6 candidates with separate 4 TCP/2 TLS workers, under the unchanged discovery budget. No IPv6 work may starve IPv4. DNS/history-derived IPv6 neighbors stay within allowed ranges; do not import upstream region patterns/seeds or claim full /64 enumeration. IPv6 availability changes invalidate routes/pools. No complete IPv6 snapshot is bundled; catalog/cache failure retains the limited IPv4 bootstrap, never widens ownership based on DNS alone. Keep OAuth SDK networking and signing identity unchanged.

BrowseReconnect tracks browser session/path attempts independently of rendering. Restore triggers a first listing, path changes reload once, and transient network failures get at most one delayed retry after the 10s discovery cooldown (11s delay). Preserve failed append pagination and visible files. A completed user check may repair a failed list once; healthy lists never refresh from repeated ticks/checks. Offline/busy/checking states defer work. Authorization, certificate, HTTP rejection and protocol errors do not schedule delayed recovery. BROWSE_AUTOCONNECT uses only fixed reason codes. Do not reset routes or launch consent for browser recovery.

RememberedAuthorization stores only the last Google account selector and local management choice in private, backup-excluded preferences. Access and refresh tokens are never persisted. Restore uses the official SDK for the selected account, is application-owned and single-flight, and never launches consent UI automatically. Require actual matching account/grants; wider cached grants cannot enable writes for a read-only profile. Logout/revoke forget the profile and invalidate old callbacks; API 401 requires interaction instead of an automatic reconnect loop. Each silent restore attempt times out after 30s, retains the profile on temporary failures and never switches accounts. The browser waits for an online path before restoration. Only SDK NETWORK_ERROR (7) and TIMEOUT (15) permit one additional silent attempt after 5s on the same network generation; a changed path starts a fresh bounded cycle. Configuration/cancellation/consent errors and API 401 never auto-retry. Recovery belongs to RememberedAuthorization, so recreation does not reset its budget. AUTH_RESTORE_RETRY logs only the prior numeric SDK status.

ConnectionHealth is bounded in-memory evidence for API and download services, separate from account authorization and cached route hints. ConnectionActivity observes it without starting probes on page entry. Only real probe/HTTP/transfer outcomes update evidence; a content root response is not a completed download. Network/policy resets invalidate old tickets; newer results beat older callbacks, body failures invalidate header-only success and UI verification ages out after five minutes independently of the route cache. System-network mode supports the same credential-free check. Show VPN presence without claiming a pinned socket bypasses VPN/TUN.

TransferActivity is a non-exported task-observation screen, reached directly from the browser transfer dock/menu and foreground notification. It must not start/restart transfers or show/focus the public-link form. MainActivity only owns the public download form. Keep Home and Files as the two bottom destinations. Existing API and secondary file actions remain available. Do not claim a persistent history/queue: the detail screen observes only the current/last process-local Snapshot.

Theme policy: values/styles.xml defines shared Material component styles; values/colors.xml and values-night/colors.xml supply complete role palettes, including secondary containers, fixed/inverse roles and neutral surface levels. Do not leave inherited purple secondary/tertiary roles in the blue Drive-style theme. Keep native Material state lists/ripples/disabled states. Primary actions use filled buttons, low-emphasis browser actions use text buttons, New uses a 16dp-corner tonal FAB. Keep 48dp touch targets and two navigation destinations.

Navigation policy: auxiliary pages use AppScreens CLEAR_TOP|SINGLE_TOP intents to prevent cyclic task stacks while retaining existing form state. Browser menu has grouped view/transfer/settings actions; connection status is reached from the visible indicator or Settings, with checks centralized in ConnectionActivity. FileMenu contains direct, non-duplicated actions; trash permits only details/restore/permanent deletion and shared-drive roots only open/details. Rendering a menu never asks for write authorization; actual selected writes retain managementReady/live lease checks and destructive confirmations. Stale file menus reject selection after requestVersion changes. Back can clear an active search during loading, while clearing only a draft does not issue a request; root Back restores its callback after delegating to the system. Home's recent heading does not open the file-library chooser. See docs/UI_FLOW_REVIEW.md.

## Source layout

Android component entrypoints remain in app/src/main/java/dev/gdirect/lite/ to preserve component identity. Helpers and matching JVM tests use auth/, network/, drive/, transfer/, preview/, diagnostics/ and ui/ packages. See docs/ARCHITECTURE.md for key code. Keep internal state private and cross-package APIs narrow; public Java APIs are in-process, not exported Android components.

The original ZIP now lives in docs/history/prototype/ with identical bytes. Icon design sources are in docs/design/. Standalone checks are in tools/checks/, and the offline legacy inspector is in tools/legacy-inspector/ (Gradle :inspector). The retired temporary-key generation script is removed; only the retained preview key is used for delivery.

## Workflow

Read root README, docs/README.md, docs/GOOGLE_SETUP.md and current workflow before work. Keep completed, verified work on main and preserve Git history. Temporary branches or PRs may be used when useful, but integrate completed work and remove merged temporary branches. Never force-push or rewrite published history without explicit instruction.

Run bash tools/check.sh for source verification. New network logic needs meaningful failure/TLS/protocol tests; run appropriate checks without repeated unrelated test cycles. New dependencies require license review and tools/refresh-notices.py. Build outputs stay ignored. Keep current docs factual and put historical evidence in docs/history/ instead of appending contradictory current instructions.

Complete a coherent functional phase before handing over one traceable APK. CI must validate actual APK identity before artifacts; random debug builds are internal checks, not compatible upgrades. Record the changes, actual checks and remaining device limits in the release notes or PR. All earlier evidence is preserved in docs/history/AGENTS_THROUGH_0_6.md, not binding as current state.
