# Android 数据连接

行为参考已核对原仓库提交 `48f413458f84c55a0d8878340a32b9bf8fa3e2d5` 和作者博客全文 `247b8b274f9ab759688e37f57634786f2c278fc1`。Android 实现独立编写，没有导入 Rust/C++、aria2 补丁、种子或测试。

## 连接和 TLS 身份

每条路线记录实际 IP、逻辑服务名、TLS 模式和验证时间。普通模式验证实际服务名；无 SNI 模式省略 SNI，仍验证实际服务名。新增 Google 前端模式：URL/SNI/证书名称为固定的 g.cn，HTTP Host 保持真实 Google 服务名。采用 HTTP/1.1 防止 HTTP/2 跨 origin 复用混淆。改写前检查逻辑 origin，非 API 内容服务不能携带账户凭据或资源密钥。

自有 Google HTTP 请求只信任独立 KeyStore 的 GTS Root R1–R4，不合并系统或用户安装 CA。根缺失、过期或指纹改变时失败关闭，保留原 emSign 排除作为额外防护。不使用泄露私钥，不关闭证书验证。来源、MPL-2.0 条款和摘要见 [TRUST_ROOTS.md](TRUST_ROOTS.md)。APK 签名不变。

## 目录请求与取消（0.8.1）

0.8.6 手动检测使用 DirectRoutes.check：已有缓存也会进行实际匿名服务验证，保留其他健康备用项；没有缓存时走原有有界发现。检测开始不调用全局 reset、不清连接池，不使正在加载目录的请求失效。真实网络/模式变化仍清理旧路径；取消或缓存写入失败不淘汰健康路线。

程序更新底部导航时不触发目录请求；主动刷新、切换范围和分页仍按用户操作执行。响应正文读取失败时先区分主动取消/账户或网络失效，取消不淘汰正常缓存；真实断流或超时仍淘汰该 IP/TLS 组合。

Drive 元数据 GET 每次 HTTP 尝试最多连接 5 秒、读取空闲 8 秒、整次请求 12 秒（包括 TLS、响应头与正文），保留调用方更短的连接/读取时限及客户端更短的整体时限。OkHttp 整体超时归类 TIMEOUT；响应前至多尝试两条路线，幂等读取仍受原有上层重试约束。选线发现预算独立，不含在这 12 秒中。文件内容 alt=media、导出、Range、内容域名和上传/写操作不受元数据整体时限影响，避免中止大文件。

## 三种连接选择

- 默认“仅 Google 前端”：有有效官方列表时，所有候选和缓存受 goog.json 减去 cloud.json 约束；官方列表暂不可达时，范围缩小为下述内置公开报告中的三个 /24，不开放任意地址。
- “自动直连（允许已知中转）”：明确说明并确认后，允许固定的第三方中转 183.56.143.147 作为额外候选；状态明确标记归属。范围列表不可达时，仅此模式可尝试该固定端点，不开放任意中转。同意后冷发现优先验证它；不保证可用。
- “系统网络”：遵循设备 DNS/代理，但自有 HTTP 仍校验 Google 专用根，不能通过安装非 Google CA 解密。Google Play 服务的授权网络不由应用 TLS 配置控制。

原作者报告该中转透传 TCP、保持 Google 端到端 TLS；本环境未作公网实测。运营者能看到客户端 IP、连接时间、流量大小和部分模式的服务域名。TLS 验证约束内容接收方，不证明物理路线或永久可用。

## 分阶段发现和备用连接

0.8.5 在此基础上加入 IPv6/AAAA、128 位 Google/Cloud 范围相减和双族隔离队列。IPv4 原有 512 候选与 24 TCP/6 TLS 线程保留；IPv6 另有最多 128 候选、4 TCP/2 TLS 线程，仍受总发现预算限制。具体来源、启用条件与冷启动边界见 [IPv6 Java 核心](IPV6.md)。下面的 IPv4 引导候选继续保留。

1. 系统网络获取官方 goog.json/cloud.json：每份最多 1 MiB/2.5 秒，禁止跳转，检查格式与至少 20 个 IPv4 前缀，独立集合相减。私有 AtomicFile 缓存每周更新，更新失败保留最多 30 天的成功缓存；冷启动失败退避一分钟，重新检测/切网可清退避。
2. 收集系统异步 DNS、Google Public DNS HTTPS JSON 和历史地址，按范围过滤。加密 DNS 使用官方 8.8.8.8/8.8.4.4 引导，正常/无 SNI 均验证 dns.google；无账户、文件或用户子网信息。
3. 先验证快速候选，最多约 10 秒；首次成功后额外收集最多 800ms 的结果，保存最多八个 IP/TLS 组合，不等于八个独立 IP。快速路径成功不会等待大范围 TCP 扫描。
4. 快速候选失败才扩大扫描：最多 512 个官方范围候选，优先独立观察到的地址及 /24 邻域，其余随机抽样。没有原项目种子或主机偏移资产。24 个 TCP 工作者、单连接最多 1.2 秒；TCP 与后续 TLS 流水线同时推进，不在前 32 个 TCP 应答处停止，也不把扩大候选截断为 48 个。刚刚失败的快速地址不在同一轮重复排队。
5. TCP 应答后立即进入最多六个 TLS/HTTP 工作者的验证队列，检查三种模式；不等待全批 TCP 结束。API 要求预期 401 JSON；其他内容域名检查对应 HTTPS/HTTP 响应。没有自有公开 Drive 测试文件，因此不能将根路径 HTTP 状态称为真实下载验证。
6. 整体发现预算 45 秒（含 DNS/TCP/TLS，不含最初官方列表）；验证组合缓存 24 小时，失败组合从持久池移除并短暂抑制。缓存身份失败后优先验证同 IP 的其他 TLS 身份，恢复窗口最多 5.5 秒且不超过总预算四分之一，成功立即返回、不再等待新 DNS。GET 在响应前有界换线；写操作不自动重放。切网清除路线/连接池，旧网络结果不能写回。下载分块仍需强 ETag、If-Range、Content-Range 和最终校验。

本项目在每段独立选择 .100 和 .132，共六个优先候选。**报告验证的是网段中的一组地址，不是这六个地址逐一的可用证据**；元数据、设置页面与文档均明确区分。在当前网络通过 Google TLS/服务探测后，才会成为可发送文件请求的路线；从未把打包地址直接写为“已验证”。

首次官方列表下载失败时，使用这个有限子集进行启动验证和有界邻域扫描；取消不触发回退。取得新官方列表后立即以它为准，Cloud 范围或已移出的内置候选会被排除，不能因为在包内就豁免。旧缓存中的子集以外地址在此模式下不被使用。当前状态标注内置候选模式；连接设置可查看来源和日期。

这是小规模引导，不是内置完整官方快照，也不承诺所有地区/运营商可用。官方列表失败仍按现有退避重试，不改变 GTS 信任库、授权系统网络或第三方中转的明确选择。

## 私人文件内容跳转

初始私人请求只接受精确 www.googleapis.com Drive API origin/路径。仅 alt=media 或导出 GET 可跟随最多四次 HTTPS 跳转；目标限定 drive.usercontent.google.com 或 googleusercontent.com 子域，拒绝用户信息、非 443 端口和 fragment。每次重建最小请求，不发送访问令牌、资源密钥、Cookie 或 Referer，只保留必要 Range/If-Range/identity 编码。元数据与写操作仍拒绝跳转，会话在跳转前和发送前检查。

使用官方 Android AuthorizationClient，访问令牌仅在内存。登录、重新获取令牌和撤销需要 Google Play 服务的系统网络。原桌面 0.9.0 的自管刷新令牌直连没有实现。普通更新无需重新注册 Android OAuth 客户端。

## 验证边界

回环 TLS 测试实际观察 SNI、Host、证书拒绝及授权头；协议测试检查跳转剥离/循环、分块版本、备用池、扩大发现、取消、切网和范围退避。APK 检查包名、版本、提交、原签名和根证书包。云环境没有绕过网络策略直拨公网 IP 或借 CI 作代理。

真实账号、设备和运营商网络的验证范围见 [设备与网络验收](ACCEPTANCE.md)。

## 统一设置与检测生命周期（0.7.0）

入口为“⋮ → 设置 → 连接”，与公开链接工具共用同一设置页；无需先进入下载工具。设置不自动发起检测：日常浏览/传输按需选线，也可主动重新检测 API 与内容服务。手动检测由应用持有，单次执行，重复点击不另开线程；离开/旋转页面不取消，取消完成前不能重启。检测不携带用户授权或私人文件信息，结果只在本进程保留；不等同真实文件下载验收。

模式采用 AndroidX ListPreference 与 Material 单选框，两个底层标记一次性保存。检测期间选择新模式会先取消旧检测，再应用选择；传输期间显示停止当前传输后的切换限制。同一模式重复选择不重置状态，实际切换会清除旧路线/连接池及上次检测结果。切网取消旧手动检测并使旧路线失效。失败、取消与成功分别显示，不将“仍在取消”当作已停止。并行连接数移入传输设置，只影响后续下载。高级手动 IP 只影响单次公开下载，不改变全局私人文件路由。

## 发送边界与历史提示复核

实际请求记录创建时的网络/模式代次。切网、模式改变推进代次；手动重检只重新验证缓存路线，不推进全局代次；系统、自动、单次手动 IP 请求使用同一代次检查。路由发现前后、客户端选择后、TLS 完成后实际发送 HTTP 头/正文之前，再检查账户会话与网络代次，失效请求停止发送。网络变化以 SocketException 交给已有有界只读重试重新打开连接；写入不自动重放。已发送的操作不能撤回，仍需核对服务端结果。账户变化/主动取消不会把健康端点标记为故障，旧代次的失败也不能剔除新代次的路线。

官方列表不可达时，之前成功但仍落在有限子集内的地址保留为待验证提示；最多两个历史提示排在内置候选前，不挤掉六个内置提示。官方列表可用时也受最新非 Cloud 范围限制。历史只改变尝试顺序，不能跳过当前 TLS/服务验证。连接失败保留凭据无关的分服务报告，通用异常仍不直接展示内部详情。

回归证据：旧实现的“TLS 期间使会话失效”本地测试确实失败（HTTP 请求仍可送出）；修复后覆盖三种 TLS 模式，断言服务器未收到授权头/请求，并覆盖写入不发送、不重放、不误标端点。这里是回环服务器证据，不是中国运营商可达性证据。

## 0.7.1：修复模式拆分后的中转启动等待

历史提交 db055eb 默认候选包含 183.56.143.147；42c7293 纠正归属并移除它、清除旧缓存。2997422 恢复主动同意后的中转候选，但在 1820e38 中仍先执行官方范围获取及 DNS 收集，才把中转加入探测队列。因此移除默认中转和前置等待都可能延长首次连接，之前的功能测试没有覆盖这项耗时对比。

现在保持用户模式选择：有效路线缓存仍最先复用；已明确允许中转时，冷发现先对固定中转做相同的 GTS/TLS/服务验证，成功马上返回，不等官方地址列表、DNS 或额外 800ms 备用收集。0.7.1 的先行探测最多 2.5 秒；0.7.3 调整为最多 5.5 秒、仍不超过整体预算四分之一，避免先行窗口短于单次服务探测超时；失败后才加载 Google 范围及 DNS，进入原有 Google 前端发现。默认/明确选择的“仅 Google”不尝试中转，自动模式不会替用户重新同意。授权 SDK 的系统网络未改变。

复现实验：`bash tools/benchmark-relay-startup.sh 1820e38`。同一个本地探测回调，模拟范围/DNS 前置等待 1500ms。一次本地观察旧版 cold 1566ms、更新后 45ms，范围调用次数由 1 变 0；热缓存均 0ms。这是合成控制流测量，探测回调并非真实公网/TLS，不能预测中转在某个运营商的实际速度。TLS 验证本身仍由独立回环测试覆盖；新增回归检查成功时不触发慢来源、故障有预算回退、Google-only 不访问中转及取消不继续扫描。


## 0.7.3：纯 Google 退化修复

维护者提供的 0.7.1 诊断显示授权成功、包名及固定签名匹配，开 VPN 后缓存了 192.179.50.100 的标准 TLS。问题定位到数据路径；更新不涉及 Google Cloud 重新登记。

已实际在旧实现上复现并修复三项回归：扩大候选的第 49 项以后被丢弃；扩大阶段重试同一批快速失败地址；缓存身份失效后未先换同 IP 的 TLS 身份。另移除运行路径中的“先取前 32 个 TCP 应答、再验证服务”屏障，使用 RouteProbeQueue 同时推进 24 TCP/6 TLS，后续 Google Drive 前端不会因为前面的应答只服务其他 Google 产品而被提前丢弃。

网络标识或 VPN 存在状态变化时清线路/连接池。除回调外，请求打开和发送前也读取当前路径，防止回调延迟时继续发送旧代次请求。NetworkPathTracker 的网络标识仅用于内存判定，不写入导出日志。

9 项新增测试包含实际回环 TLS：先尝试缓存的标准身份，严格主机名验证失败后用 g.cn 身份验证无凭据 401，再完成带测试令牌的正文读取。两变体各 143 项测试，保留错误证书拒绝、下载跳转剥离凭据和写操作不重放检查。默认仍为“仅 Google 直连”，修复不依赖开启中转。


## 浏览器自动连接与恢复

进入浏览器时，已有授权立即发起目录读取；官方 SDK 静默恢复完成后，独立的 BrowseReconnect 以会话代次触发首次读取，不依赖 UI 的 wasConnected 标记。实际目录请求使用原有自动选路，状态入口只负责查看，进入页面不启动扫描。账户恢复本身也有独立的有限恢复：离线等待联网；SDK 状态 7/15 在同一网络 5 秒后最多重试一次，换网络后开始新一轮。Google 要求确认、配置错误或 API 401 仍等待用户操作，不因数据端点探测成功而绕过。

网络代次变化时，浏览器等待在途读取/编辑完成、网络在线后自动刷新当前目录。临时网络失败后等待 11 秒（超过发现失败的 10 秒抑制），只追加一次重试；再次失败保留重试按钮。恢复读取保留当前范围、查询及排序，分页重试继续同一页，不清空先前文件。权限、授权、证书和响应格式问题不触发该延迟重试。正常目录、状态过期和重复渲染都不定时刷新。

已失败的目录在用户手动检测完成且 API 验证成功后自动衔接一次；活跃检测、离线与编辑期间暂停调度，切换账户丢弃旧尝试。重连不重置全局路线，也不自动弹授权页或重放写操作。日志只增加固定原因码，测试不连接公网。

## 0.7.5：连接状态与实际结果

主界面顶部状态行、“连接状态”菜单和“设置 → 连接状态”打开同一页面。ConnectionHealth 只在进程内保存 API/下载两项的固定状态、证据种类、公开路线、HTTP 状态与单调时钟年龄；不记录账户、文件、URL 或令牌。账户授权从 DriveSession 与恢复状态单独读取。

缓存路线选择本身不变成“已连接”；无凭据 API 探测的预期 401 是线路证据，真实请求的 401 则提示授权处理。内容根路径的 2xx–4xx 响应只显示“文件服务可响应，尚未完成实际下载”；只有前台下载真正完成并保存后显示最近下载完成。HTTP 403/404 等说明 Google 已响应，将权限/文件问题与连接失败分开。正文断流会覆盖此前的 HTTP 头部成功。

每次请求绑定网络/模式代次和序号；旧代次、晚到的旧请求结果不能覆盖新状态。切网、VPN 变化和清线清除旧证据；五分钟后状态变为需重确认，不影响 24 小时路线缓存本身。系统网络模式也可做相同的无凭据检查，不强制改为直连。页面不会因为 Wi-Fi、SDK 授权或一个缓存 IP 就显示全链路成功。

检查由应用持有并记录开始/结束时间，页面只观察；进入状态页不启动扫描，离开不取消。新状态通过真实回环 TLS 的 HTTP 403、正文断流、观察器故障隔离，以及过期/切网/迟到回调等 24 项回归验证。当前未执行手机视觉和真实运营商网络验收。
